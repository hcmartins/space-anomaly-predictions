# space-anomaly-predictions

Code for a PhD thesis on forecasting space-weather anomalies in two domains and fusing them:

| Package | Thesis chapter | What it does |
|---|---|---|
| [`src/solar`](src/solar) | Chapter 3 | Solar flare forecasting from GOES XRS irradiance and SDO/HMI SHARP magnetic descriptors (baselines, classical models, LSTM) |
| [`src/martian`](src/martian) | Chapter 4 | Martian dust-storm detection and dust-optical-depth regression from EMM/EMIRS retrievals and the Montabone dust climatology |
| [`src/cross-domain`](src/cross-domain) | Chapter 5 | Representation alignment and attention fusion between the frozen solar and Martian encoders (A1–A7 ablation, 5-seed uncertainty sweep) |

Chapter 6 results (evaluation, significance tests, calibration, threshold study) are computed by analysis scripts in each package from the canonical runs listed below.

Each package has its own README and `planning/` documentation with stage-by-stage detail. This page covers setup and the order to run things in.

## Repository layout

```
src/
  solar/          configs/ data_sources/ preprocessing/ labeling/ splitting/ modeling/ tests/ planning/
  martian/        configs/ data_sources/ preprocessing/ labeling/ splitting/ modeling/ evaluation/ mars/ tests/ planning/
  cross-domain/   configs/ encoders/ fusion/ training/ evaluation/ tests/
  make_thesis_figures.py, chapter6_figures.py   results figures from the canonical outputs
requirements.txt  pinned environment used for the canonical runs
```

Not in the repository (regenerated by the steps below): raw data caches (`data_cache/`, ~28 GB for Mars and ~6 GB for solar), model checkpoints (`checkpoints/`), and full run outputs. Small summaries of the canonical runs (manifests, metrics, reports, thesis tables) are committed under `src/martian/outputs/real/` and `src/cross-domain/outputs/`.

## Setup

### 1. Windows: enable long paths before cloning

Some committed output paths exceed Windows' 260-character limit, so a clone or checkout fails with `Filename too long` unless long paths are enabled:

```bash
git config --global core.longpaths true
git clone https://github.com/hcmartins/space-anomaly-predictions.git
```

Keeping the clone in a short directory (e.g. `C:\projects\`) also helps.

### 2. Python environment

All three packages run in one environment. The canonical results were produced with Python 3.14.6, CPU only (Intel i7-1255U, 16 GB RAM, no GPU), using the exact versions in [`requirements.txt`](requirements.txt):

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows;  source .venv/bin/activate on Linux/macOS
pip install -r requirements.txt
```

The per-package `requirements.txt` / `environment.yml` files list older version ranges from earlier in the project. Use the root file to reproduce the reported results.

### 3. Credentials for data download

| Variable | Used by | How to get it |
|---|---|---|
| `JSOC_EMAIL` | SHARP download (`src/solar`) | Free registration at http://jsoc.stanford.edu/ajax/register_email.html. Alternatively, set `jsoc_email` in `src/solar/configs/sharp.yaml`. |
| `EMM_SDC_USER`, `EMM_SDC_PASS` | EMIRS download (`src/martian/download_emirs_sdc.py`) | An account on the EMM Science Data Center, https://sdc.emiratesmarsmission.ae. You are prompted for them if they are not set. |

### 4. Working directory

**Every command below is run from inside the package directory** (`cd src/solar`, `cd src/martian` or `cd src/cross-domain`). The packages use unprefixed imports (`from preprocessing... import ...`), and these resolve only from there.

## Run order

The fusion stage needs the trained solar and Martian encoders, so run solar and Mars first (in either order), then cross-domain, then the analysis scripts.

```
solar ingest ──► solar classical run ──► solar GOES+SHARP LSTM ──┐
                                                                  ├──► fusion sweep ──► Chapter 5/6 fusion analyses
Mars download ──► climatology ──► mars.run_all ──► promote LSTM ─┘
                                        └──► Chapter 4/6 Mars analyses
```

### Solar (`cd src/solar`)

```bash
# 1. Ingest GOES XRS + SHARP for 2010-05-01..2025-07-24 into data_cache/ (SHARP queries are chunked adaptively)
python -m ingest --config configs/solar_ingest.yaml

# 2. Classical pipeline: QC, alignment, gap-filling, features, labels, chronological split, baselines + classical models
python -m run_pipeline \
    --goes-csv data_cache/goes/normalized/goes_xrs_normalized_full_20100501_20250724.csv \
    --sharp-csv data_cache/sharp/normalized/sharp_normalized_full_20100501_20250724.csv \
    --run-name real_full_20100501_20250724

# 3. GOES+SHARP LSTM (the solar encoder used for fusion); reuses step 2's QC'd rows and split
python -m run_pipeline_sequence --base-run-name real_full_20100501_20250724 \
    --run-name real_full_sequence_goes_sharp_20100501_20250724 --include-sharp
```

Outputs go to `results/<run-name>/`, and the LSTM checkpoint is written to `checkpoints/real_full_sequence_goes_sharp_20100501_20250724/lstm_label_primary.pt`. The GOES-only LSTM is the same command without `--include-sharp`, using `--run-name real_full_sequence_20100501_20250724`.

Chapter 3/6 analyses, which use the trained models and do no retraining:

```bash
python export_baseline_predictions.py
python export_lstm_predictions.py --variant goes
python export_lstm_predictions.py --variant goes_sharp
python analyze_common_subset.py            # Section 3.8 common-subset comparison
python analyze_chapter6_supplementary.py   # confusion matrices, PR curves, calibration, McNemar
python reconcile_split_counts.py           # Table 3.2 vs trained-model split counts
```

### Mars (`cd src/martian`)

```bash
# 1. Data
python download_emirs_sdc.py --end-date 2025-01-14   # EMIRS L3 FITS, 2021-02-20..2025-01-14, into data_cache/emirs/raw
```

Also place these in `data_cache/`:
- `griddedcdod_MY34_v2-5.nc`, `griddedcdod_MY35_v2-5.nc`, `griddedcdod_MY36_v2-5.nc`: the Montabone et al. gridded column dust optical depth (Montabone et al. 2015, doi:10.1016/j.icarus.2014.12.034; 2019, doi:10.1029/2019JE006111).
- `emm_exi_dust_storms/DustStormDatabaseEXI_MY36_V1.xlsx`: the Guha et al. (2024) EMM-EXI MY36 dust-storm database, doi:10.5281/zenodo.10275974. It is used for the independent label validation (Table 4.6).

```bash
# 2. Build the dust climatology (mu_clim / sigma_clim) from the Montabone files
python build_mcd_climatology_from_montabone.py

# 3. Full pipeline: 15 steps from QC to final report, seed 42 (configs/run.yaml)
python -m mars.run_all --config configs/run.yaml
```

Each run writes a new, never-overwritten directory `outputs/real/run_<UTC timestamp>_seed42/`. The canonical run is `run_20261004T080014968911Z_seed42`.

**Promote the storm-detection LSTM for fusion.** The cross-domain encoder loads `checkpoints/task_storm_detection/lstm_w3_h1.pt`. This is a copy of the run's `models/storm_detection/` directory; the canonical checkpoint is byte-identical to the one in the canonical run:

```bash
cp -r outputs/real/<run_id>/models/storm_detection/. checkpoints/task_storm_detection/
```

Chapter 4/6 analyses, which use frozen models and do no retraining. Run the supplement first: `run_newrun_followups.py`, `run_local_time_sensitivity.py` and `report_residual_items.py` read its predictions.

```bash
python run_chapter6_supplementary.py --run-dir outputs/real/<run_id>   # writes outputs/real/chapter6_supplementary_<UTC>/
python run_newrun_followups.py
python run_local_time_sensitivity.py
python report_residual_items.py
python run_retrieval_uncertainty_propagation.py --run-dir outputs/real/<run_id>
python run_missing_data_sensitivity_sweep.py
python generate_figure_4_5_raw_data.py && python generate_chapter4_preprocessing_figures.py
```

### Cross-domain fusion (`cd src/cross-domain`)

```bash
python run_uncertainty_sweep.py   # A1-A7 ablation at seeds 44-48 + bootstrap/paired analysis
```

This loads the two frozen encoders from `configs/encoders.yaml`. On the first run it builds each domain's sequence-tensor export by calling that package's `export_fusion_sequences.py` (see `fusion_data.py`). `run_ablation.py --seed <n>` runs a single seed, and `run_fusion.py` trains only the full model (A7). The canonical sweep is `outputs/uncertainty_sweep_20261004T092140396722Z/`.

Chapter 5/6 analyses on the sweep's saved predictions. They also read the Mars Chapter 6 supplement (`chapter6_supplementary_20261004T093226Z`) and depend on each other, so run them after the Mars analyses and in this order:

```bash
python run_fusion_supplementary.py
python run_a5_vs_a7_paired.py
python run_fusion_code_audit.py
python run_fusion_code_audit_paired.py
python run_recover_attention.py           # retrains A3/A4/A6/A7 per seed and accepts only exact matches to the sweep
python run_prototype_rescore.py
python run_prototype_paired.py
python run_nontransductive_primary.py
python run_failure_case_catalogue.py
```

### Thesis figures (`cd src`)

```bash
python make_thesis_figures.py   # Mars/solar PR + reliability, fusion within-season TSS -> thesis_figures/
```

## Things to know when reproducing

- **Run IDs are hardcoded in the analysis scripts.** A fresh Mars run gets a new timestamped ID. Most analysis scripts, `src/cross-domain/fusion_data.py` (`MARTIAN_EXPORT_DIR`) and `src/cross-domain/configs/encoders.yaml` name the canonical IDs above in constants near the top of each file. Update them, or pass `--run-dir` where a script accepts it, to point at your own run.
- **Seeds.** Mars uses seed 42 (`configs/run.yaml`). Fusion uses seeds 44–48 (`run_uncertainty_sweep.py`), and bootstrap resampling uses `default_rng(20260818)`. All training is on CPU, so exact reproduction also needs the pinned package versions.
- **Data downloads change over time.** The solar ingest window is fixed in `configs/solar_ingest.yaml` and `configs/sharp.yaml`. The EMIRS download defaults to "until today", so pass `--end-date 2025-01-14` to match the archive used here (7,445 files).

## Tests

```bash
cd src/solar && python -m pytest -q          # 196 tests
cd src/martian && python -m pytest -q        # 381 tests
cd src/cross-domain && python -m pytest -q   # 91 tests
```

The solar and Mars suites use synthetic fixtures and need no data. Sixteen cross-domain tests load the real trained encoder checkpoints, so they fail until the solar LSTM and the promoted Mars LSTM exist.
